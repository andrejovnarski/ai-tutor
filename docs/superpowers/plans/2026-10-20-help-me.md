# Help me Implementation Plan

> **For agentic workers:** executed by Codex one task at a time through `docs/codex/HANDOFF.md`
> (Claude writes each task there, owns git, runs db/e2e, reviews). Steps use checkbox (`- [ ]`) syntax.

**Goal:** a "Help me" button on every problem that gives a hint + teaching picture (Help 1), then a worked
answer the child types (Help 2), scored like a quiet miss and stored as `helped`.

**Architecture:** a pure `help()` in the session engine beside `answer()`; the server mirrors `playAnswer` with
`playHelp` and a `/help` route returning the answer response shape; the client reuses its `answered` reducer
path, so only a new request and a button are added.

**Tech Stack:** Next.js 16 (read `node_modules/next/dist/docs/` before touching Next APIs), Supabase, Vitest,
Playwright.

**Spec:** `docs/superpowers/specs/2026-10-20-help-me-design.md`

## Global Constraints

- Help is never shown as wrong: no red, cross, shake, negative sound, or help counter on the kid screen.
- Help 1 line never states the answer (number guard); Help 2 may (`revealed: true`).
- Max two help levels per problem; the button is hidden at level 2 and on the end card.
- Attempt rows for help: `result: "helped"`, `answer: null`, `mistakeTag: null`.
- A helped problem never adds to `firstTryCorrect`.
- Old saved sessions (no `pending.help`) behave as level 0.
- `"help"` is appended to the end of `EVENTS` in `src/server/play.ts` so existing canned seeds don't shift.
- Button accessible name exactly `Help me`.
- Weekly email content unchanged.

## Review Focus

1. **Double tap on Help me** (two requests, same version) → one level advance, the second gets 409 + current
   turn. Test in Task 2 (`playHelp` with stale version).
2. **Reload after Help 1 / Help 2** → same hint/demo state comes back (pending.help persisted, `PublicTurn.help`
   from the saved pending). Test in Task 1 (`nextTurn` keeps `help`) and Task 3 (e2e reload).
3. **Help on the last placement probe item** → placement finishes, the supported try still shows, its answer
   doesn't touch placement. Test in Task 1.
4. **Help 1 in practice tipping a struggle** (`isStruggling`) → prerequisite check set exactly as after a wrong
   answer; the supported try still comes first. Test in Task 1.
5. **Help tapped while a request is in flight / offline** → ignored like a second answer tap (busy guard). Test
   in Task 3 (`usePlay` help while busy does not fetch).
